## Verdict

**Mostly consistent. One high finding should be fixed before the skeleton story is written.** The amendment keeps the PRD's quiet requirements that matter most: one origin with relative `/api` calls, no session work on the Next.js server, Landing without a cookie, fonts and images self-hosted, `next/font` and `next/image` excluded, telemetry off for builds, `/docs` off because Swagger UI loads from a CDN, the time facts sent by the server, and the HTTPS order (plain HTTP in the Core, then HTTPS before any Manage link). NFR-2 holds: the PRD asks for one API that decides every rule, not for one server, so the earlier "a second Node server is against NFR-2" was the spine's own reading and needs no PRD change. Not adopting TypeScript, Tailwind and shadcn follows §8.2 and FR-22.

The gaps cluster in three places:
- **The fresh clone.** AD-14 mounts a git-ignored file into the compose stack, so a fresh clone either fails to start or gets a stray directory (H1). The documented Administrator command does not reach the examiner's database (M6).
- **What Next.js brings by default.** Its default error and 404 pages, its scaffold logos and favicon, and the focus-on-navigation rule meeting the "Before you come" anchor are not covered by any rule (M3, M4, M5).
- **Tests and README duties that lost their home.** The browser-side FR-21 checks have no test layer (M2), and the README no longer states the FR-24 cookie limit (M1).

Several PRD and addendum sentences still describe the earlier setup, or are slightly stronger than the spine delivers. They are listed at the end so that Lisa can update the sources.

Severity: **high** = the spine contradicts the PRD or claims coverage it does not give, so a story built on the spine fails a PRD consequence. **Medium** = a testable PRD consequence with no architectural home, where stories are likely to diverge. **Low** = a clarification, an internal inconsistency, a test obligation or a documentation duty.

Counts: **1 high, 6 medium, 13 low.** **9 PRD and addendum sentences to update** (plus 3 in `EXPERIENCE.md`).

## PRD sentences to update

Each item quotes the current sentence exactly and gives the reason. Wording suggestions are optional; Lisa decides.

1. **prd.md §4.7 Description:** "The website and the API are served only over HTTPS, so passwords, sessions and Manage links never travel unencrypted."
   TLS ends at Caddy, and the hop from Caddy to the backend and the frontend is plain HTTP on the internal compose network (**L1**). Suggest: "… never travel unencrypted between the browser and the platform; behind the proxy, traffic stays on the machine's internal network." Needs Lisa's confirmation.
2. **prd.md FR-24, third consequence:** "On `localhost`, browsers send Secure cookies over plain HTTP anyway, so the local test checks the cookie attributes and that the HTTP listener never reads a cookie."
   Optional. The "HTTP listener" is now Caddy's redirect. Suggest: "… checks the cookie attributes and that a plain-HTTP request carrying the cookie is only redirected and changes nothing" (AD-27 HT-3).
3. **prd.md NFR-1:** "It needs no keys, paid accounts or external services."
   The first build downloads public images and packages (**L3**). Suggest: "… or external services at run time; the first build downloads public images and packages."
4. **prd.md NFR-1:** "The examiner installs Python with uv, Node.js and Docker, and nothing else (Lisa, 2026-10-30; confirmed with the change to PostgreSQL on 2026-11-03)."
   Playwright downloads its own Chromium for the tests (**L2**). Either accept it as part of "Python with uv" and say so, or name it.
5. **prd.md NFR-1:** "One more command runs all tests; uv and Node.js are needed for the tests and for development."
   The spine has two one-time preparation commands before `uv run pytest`, and the tests also use Docker (**L2**). Suggest: "One more command runs all tests, after two one-time preparation commands; the tests use uv, Node.js and Docker."
6. **prd.md DR-2, first bullet:** "how to install and start the backend and the frontend;"
   The examiner now starts everything with one compose command. Suggest: "how to start the platform with one command (NFR-1), and how to run the backend and the frontend for development;".
